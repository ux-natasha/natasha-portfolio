## Anti-Patterns Verdict

**LLM assessment**: Not AI slop. Bespoke construction throughout — the folder is built from stacked hard-edged `box-shadow`s (no blur standing in for depth), the serif/mono pairing is deliberate and documented, pink is genuinely rationed to interaction states (`--rose` vs `--rose-ink` split by function, not by taste), and there's no gradient text, no bento grid, no pill buttons, no generic hero-metric template. If anything the risk runs the opposite direction from generic — the site risks feeling *over-engineered* relative to its current content volume (see P1 below).

**Deterministic scan**: `detect.mjs --json` against `app/page.tsx`, `Cover.tsx`, `Opening.tsx`, `ShelfView.tsx`, `Spine.tsx`, `Plate.tsx`, `Workspace.tsx`, `PageTransition.tsx`, `MiniMasthead.tsx`, `Foot.tsx` returned **zero findings, exit code 0** across all 10 files. No side-stripe borders, no gradient text, no glassmorphism, no eyebrow-per-section pattern, no numbered-marker reflex — mechanically corroborates the LLM's "not slop" read.

**Visual overlays**: Not available this run — no browser-automation tool is exposed in this environment (confirmed by exhaustive tool search; only a Figma screenshot tool and read-only `WebFetch` exist, neither of which supports script injection or DOM mutation). This is a tooling gap, not a claim about the app. Nothing in this report should be read as visually verified live; all findings are source-level.

## Overall Impression

This is a genuinely bespoke, well-considered piece of design engineering — the strongest part of the "AI slop" test is that it passes without qualification, on both the subjective read and the mechanical scan. The real tension isn't craft, it's scope creep against the site's own stated concept: CLAUDE.md/PRODUCT.md describe a frame around "one real folder, confidently central" with two dimmed, near-invisible future slots — but the drawer now shelves **three fully-built, fully-clickable compartments** (VPro/CCPM, The Stacks, DS2) at equal visual weight. DESIGN.md already logs this as "confirmed, not a gap" per a 2026-07-30 conversation with Natasha, so it's a deliberate interim choice, not a bug — but a cold hiring-manager read still sees three portfolio pieces of wildly different scale and stakes presented as equals, which dilutes the "CCPM is the deep centre" promise the whole site architecture is built to deliver on.

## What's Working

- **`Cover.tsx`'s three-tier interaction split** (tab click = preview, pager = step, "Read more →" = actually navigate) is reinforced by a small, honest status cue (`.tablist-cue`) rather than left ambiguous — a real UX problem solved in the open, not papered over.
- **The credit tag** (`.folder-credit.is-solo`) — a flat ink-stamped mono tag, not a pink badge — makes "who built this" a legible visual fact instead of a footnote. This is exactly the kind of fact CLAUDE.md's voice section says a generic portfolio can't fake, and it's rendered with real graphic weight.
- **`Plate.tsx`'s theme-toggle callback** — replaying the three-plane settle animation on dark-mode toggle turns a utility control into a callback to the opening's own line about "the brightness of gray." Specific and earned, not decorative.

## Priority Issues

- **[P1] Drawer shelves three full compartments at equal weight, undercutting CCPM's centrality**
  **Why it matters**: CLAUDE.md §0/§1c and PRODUCT.md's "N≥2 gate" describe the tail as *one real folder, confidently central*, with future work as dimmed, near-invisible, clearly-coming labels. `content/compartments/` now holds three fully populated, identically-styled, fully-clickable shelves (`Workspace.tsx:173-190`) — a 3-year enterprise system next to a one-day solo SQLite project, at the same visual authority. DESIGN.md logs this as a confirmed interim decision (2026-07-30), so it isn't unintentional — but a hiring-manager reader landing cold still can't tell which one is "the deep centre" from the shelf alone, which is the exact confusion CLAUDE.md's own risk note in §0 warned against.
  **Fix**: Differentiate weight — size, order, a "flagship" mark, or a visibly different treatment for CCPM's shelf vs. the other two — so the drawer still reads as "one real folder + emerging work" rather than three peers.
  **Suggested command**: `/impeccable layout`

- **[P1] Opening's Outcome row is stub-tagged but reads as a specific, finished claim**
  **Why it matters**: `content/opening.md`'s Outcome line ("the planning screen that survived shipped, and was adopted client-wide") reads as a concrete, load-bearing fact — exactly the register CLAUDE.md's voice section prizes — but it's flagged `placeholder: true` in content, and CLAUDE.md §1b explicitly forbids inventing a real achievement for this slot ("do NOT invent a real achievement"). Right now it's ambiguous whether this is real (in which case it's underselling itself by wearing stub styling) or drafted (in which case it may cross the hard rule). This sits at the single highest-stakes line on the page — the reassurance moment a hiring manager needs right after the hook.
  **Fix**: Confirm with Natasha whether this is a real, verified fact. If real, drop the placeholder treatment and let it stand at full weight. If not yet confirmed, keep the stub tag but soften the copy so it doesn't read as a settled claim.
  **Suggested command**: `/impeccable clarify`

- **[P2] Panel-level placeholder tag misrepresents three real fields as unfinished**
  **Why it matters**: The at-a-glance card's single corner "placeholder" tag (`Opening.tsx:31-33`) applies to the whole four-row panel, but only 1 of 4 rows (Outcome) is actually a stub. Role, System, and Owned are real, confirmed facts that visually inherit "unfinished" framing they don't deserve — undermining confidence in facts that are actually solid.
  **Fix**: Scope the tag to the specific stub row(s), or change the label to something like "1 of 4 fields pending" so it doesn't blanket-flag settled content.
  **Suggested command**: `/impeccable clarify`

- **[P2] "Vector Digital Labs" repeats in the first four lines of the page**
  **Why it matters**: The eyebrow and the hero role line both name the employer (`Opening.tsx:17-19`) on the one screen CLAUDE.md calls "lightest touch" — the opening's entire job is a fast, confident 10-second read, and a repeated proper noun in the first four lines reads as filler exactly where the copy needs to feel most deliberate.
  **Fix**: Drop the redundant mention, or fold it into a single line.
  **Suggested command**: `/impeccable clarify`

- **[P3] Cumulative decision load across the full scroll is heavier than the "brief moment you pass through" framing intends**
  **Why it matters**: Between the compartment strip (3 options, each with up to 4 sub-tabs), the pager, and the drawer (3 shelves + 2 dimmed slots + contact), a reader can face up to 8 distinct clickable destinations before reaching the foot — no single control exceeds the 4-option working-memory guideline, but the *cumulative* surface is busier than "a brief moment you pass through, not a second homepage" (CLAUDE.md §0) implies. Compounding this on mobile: the rail, the compartment strip, and the folder tab row are three independent `overflow-x: auto` horizontal scrollers stacked on one small screen, unverified live but a real risk for thumb/scroll-direction confusion.
  **Fix**: Re-pass this once the P1 weight-differentiation fix lands — reducing The Stacks/DS2 to a visually quieter register will likely resolve most of this on its own.
  **Suggested command**: `/impeccable adapt`

## Persona Red Flags

**Jordan (First-Timer)**: Lands on the hero, reads eyebrow → name → role → line, scrolls to "the work, in the order it was built ↓" — clear so far. But on hitting the compartment strip, sees three equally-styled, equally-clickable records with no visual signal for which one is "the real thing to read first." CLAUDE.md's own §0 risk note predicted precisely this confusion before it happened.

**Riley (Stress-Tester)**: Rapid double-clicking rail-number buttons or compartment tabs mid-`SlidingCover` transition is a plausible edge case — `SlidingCover`'s `setTimeout(600)` unmount could theoretically race a second click before `outgoing` state clears if `seq` changes twice in quick succession. Not confirmed broken from source alone; flagged for a manual double-click pass, ideally with the browser tooling this run couldn't access.

**Casey (Mobile)**: Below 880px, the rail collapses to a horizontal strip while the compartment strip and folder tab row are already independent `overflow-x: auto` regions — three separate horizontal-scroll zones stacked on one small screen is a real risk for scroll-direction confusion and thumb fatigue, though this couldn't be visually confirmed live this run (no browser tool available).
